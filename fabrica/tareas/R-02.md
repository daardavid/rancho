# Persistencia base

## Objetivo
Dejar PostgreSQL, Drizzle, las migraciones y la base de pruebas listas para que Herd y Growth guarden hechos con las reglas de `docs/architecture/persistence-strategy.md`.

## Qué hacer
- Drizzle en `apps/api/src/infrastructure/db`. Una sola secuencia de migraciones SQL generadas con la herramienta de Drizzle, guardadas en el repo y revisables.
- Comandos explícitos: `npm run db:migrate -w @rancho/api` (aplica migraciones a `DATABASE_URL`) y `npm run db:reset -w @rancho/api` (solo local; se niega a correr si `NODE_ENV=production` o si la URL no es local). El servidor nunca migra al arrancar.
- Fábrica de base de pruebas según ADR-014: con `TEST_DATABASE_URL` se conecta a ese servidor; sin ella arranca PGlite en el mismo proceso. Aplica las migraciones con el mismo código de `db:migrate`. Si no puede arrancar ninguna, la prueba falla (no se salta).
- Patrón de transacción de ADR-008: una función que abre una transacción y construye los repositorios de cada módulo atados a ella. Los servicios de aplicación reciben interfaces de repositorio, nunca la transacción de Drizzle. Sin Unit of Work genérico ni `AsyncLocalStorage`.
- Primera migración: esquemas `herd`, `growth` e `identity` vacíos, más `identity.ranch` (id UUID, nombre, `created_at`) y una semilla explícita (`npm run db:seed -w @rancho/api`) que crea el único rancho si no existe. La semilla no inventa datos del rancho: solo un nombre configurable por variable de entorno.
- Utilidad compartida de idempotencia para comandos: guardar el id de comando y una huella del contenido significativo; mismo id y misma huella devuelve el resultado guardado; misma id con otra huella da el error de dominio `idempotency_mismatch`. Pruebas de los tres casos.
- Utilidad de concurrencia optimista: `UPDATE ... WHERE id = ? AND version = ?`; cero filas da `version_conflict` y no cambia nada. Pruebas.
- `docker-compose.yml` con un PostgreSQL para datos de desarrollo (opcional para trabajar; no lo necesitan las pruebas).
- CI: servicio de PostgreSQL y `TEST_DATABASE_URL` apuntando a él.
- `.env.example` con `DATABASE_URL`, `TEST_DATABASE_URL` (comentada) y el nombre del rancho para la semilla. Sin valores reales.

## Terminado cuando
- `npm test` corre las pruebas de persistencia en PGlite sin Docker y pasan.
- Hay una prueba que abre una transacción, escribe en dos esquemas, fuerza un error y comprueba que no quedó ninguna fila; y otra que confirma ambas.
- Las pruebas de idempotencia y de `version_conflict` pasan.
- Ninguna ruta de código del servidor aplica migraciones al arrancar.

## Fuera de alcance
Tablas de animales, pesos o usuarios (vienen en sus tareas). Hosting.
