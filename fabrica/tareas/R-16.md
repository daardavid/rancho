# La fábrica espera al CI

## Objetivo
Que ningún PR de la fábrica entre a `integracion` con el CI en rojo, como pasó en INC-001.

## Qué hacer
- `.github/workflows/ci.yml`: `pull_request` corre también para la rama `integracion`.
- `fabrica/correr.py`: cuando una tarea queda aprobada, antes del merge espera los checks del PR (`gh pr checks --watch` o equivalente) con un tiempo máximo configurable en `fabrica/config.toml` (por ejemplo `[ci] esperar = true` y `timeout_min = 30`).
  - Verde: merge como hoy.
  - Rojo: guarda el log de lo que falló (`gh run view --log-failed`, las últimas líneas) en `.fabrica/trabajo/<tarea>/ci.txt` y lo trata como pruebas en rojo: otro ciclo de Cursor con ese log en sus instrucciones.
  - Se acaba el tiempo o no hay checks: se detiene con un mensaje claro y no hace merge.
- Pruebas en `fabrica/test_correr.py` de esa decisión (verde, rojo, sin checks, tiempo agotado), sin llamar a GitHub de verdad.
- Actualiza `fabrica/README.md`.
- Actualiza `docs/product/mvp-framing.md` ("Proposed MVP path") y la sección NEXT de `docs/product/master-plan.md`: INC-002 es "Todo en local" y la publicación queda para un incremento de migración después.

## Terminado cuando
- `python -m unittest discover -s fabrica -p "test_*.py"` pasa con los casos nuevos.
- `npm run lint`, `npm run typecheck`, `npm test` y `npm run test:e2e` pasan.
