# La web llega comprimida y más ligera al celular

## Objetivo
Que el celular descargue mucho menos la primera vez que abre la app (y la primera vez después de cada actualización). Ver INC-006.

## Lo que midió David (2026-11-25, en la laptop)
- `/assets/index-*.js`: 523,263 bytes, sin `content-encoding`. Comprimido con gzip en el navegador: unos 144 KB.
- `/assets/index-*.css`: 31,933 bytes, sin comprimir (unos 6 KB con gzip).
- Cinco fuentes woff2 (Archivo 700 y 800, Inter 400, 500 y 600), unos 100 KB.
- La caché ya está bien: assets con `max-age=31536000, immutable` e `index.html` con `no-store`. No se toca.
- Pantallas y API ya son rápidas (todo bajo 100 ms). No se optimiza código ni consultas en esta tarea.

## Qué hacer
- Compresión **sin dependencias nuevas de producción**: al construir la web, un script con `node:zlib` genera junto a cada asset de texto (`.js`, `.css`, `.html`, `.svg`, `.json`) su versión `.br` y `.gz`. Engánchalo al `build` de `apps/web` o al de la raíz para que `npm run local`, `npm run build` y el despliegue lo usen igual.
- `apps/api/src/http/servir-web.ts`: activa `preCompressed: true` de `@fastify/static` para que sirva `.br` o `.gz` según `Accept-Encoding`, con `Vary: Accept-Encoding`. Las reglas de caché siguen igual (assets inmutables, `index.html` sin caché).
- Las respuestas de `/api` no se comprimen en esta tarea (son de 1–2 KB).
- Fuentes: revisa qué pesos se usan de verdad en `apps/web/src` y en `docs/design/guia-visual.md`. Carga solo los necesarios (meta: 3 archivos o menos) sin cambiar cómo se ve la guía. Si un peso se usa poco, cámbialo al más cercano que ya se carga y dilo en la nota.
- `docs/development/publicar.md`: agrega una sección «Que no se duerma» con la opción de un aviso automático gratuito cada 10 minutos a `GET /api/health` (no toca la base, así Neon sí puede dormirse y no gasta sus horas). Explica la cuenta: un servicio despierto todo el mes son unas 744 horas y el plan gratis da 750. Marca «por confirmar» que las reglas de Render lo permitan y lista dos maneras de hacerlo (un servicio externo de avisos gratuito o un flujo programado de GitHub Actions) con sus límites. **No** agregues un flujo programado al repo: la URL publicada todavía no existe.

## Terminado cuando
- Prueba del servidor: con `Accept-Encoding: br` el JS llega con `content-encoding: br`; con `gzip`, con `gzip`; sin encabezado, sin comprimir. En los tres casos el contenido descomprimido es idéntico y el `cache-control` es el de hoy.
- Prueba: `index.html` sigue con `no-store`.
- Prueba del script de compresión: genera `.br` y `.gz` para los tipos de texto y no para `.woff2` ni imágenes.
- La nota de Cursor reporta los tamaños antes y después (JS, CSS y fuentes).
- `npm run lint`, `npm run typecheck`, `npm test` y `npm run test:e2e` pasan.

## Fuera de alcance
Dividir el código en partes, juntar llamadas de la API, tocar la base, PWA o modo sin conexión, publicar.
