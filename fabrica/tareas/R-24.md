# Potreros y lugar esperado

## Objetivo
Saber dónde se espera a cada animal: una lista de potreros y asignaciones con fecha, de un animal o de un grupo. Ver `TGT-MOVE-001` y "Paddock reference and expected location" en `docs/architecture/domain-boundaries.md`.

## Qué hacer
- En Herd: `PaddockReference` (id, nombre que el rancho use, nota; puede estar incompleta) y `LocationAssignment` (animal, potrero o `unknown`, desde cuándo vale, quién lo dijo). Se agregan, no se editan; el lugar vigente es la última asignación.
- Comandos: crear o renombrar potrero (con historia), asignar lugar a uno o a varios animales en una sola transacción (una asignación por animal). Idempotentes.
- No pedir hectáreas ni mapa. No afirmar que los potreros cubren el rancho.
- Asignar un lugar no es una observación del animal.
- Web con la guía visual: pantalla «Potreros» desde el menú (lista con cuántos animales se esperan en cada uno y cuántos sin lugar); en el hato, filtro por potrero y un modo de selección para «Mover a…» varios animales; en la ficha, lugar vigente y su historia.

## Terminado cuando
- Pruebas: mover un grupo escribe una asignación por animal en una transacción; el lugar vigente es el último; `unknown` es válido; una asignación no cambia la última observación.
- `npm run lint`, `npm run typecheck`, `npm test` y `npm run test:e2e` pasan.

## Fuera de alcance
Pastoreo, carga animal, GPS, verificación por potrero.
