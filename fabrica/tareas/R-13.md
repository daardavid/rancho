# Respaldo y restauración locales

## Objetivo
Que David pueda guardar toda la base local en un archivo y recuperarla, y que ese mismo archivo sirva para la migración a un PostgreSQL normal más adelante.

## Qué hacer
- `npm run respaldo`: escribe un archivo con fecha y hora en `respaldos/` (ignorada por git) con todos los esquemas de la app y sus datos.
- El formato debe poder cargarse en un PostgreSQL de servidor (SQL o el formato de `pg_dump`), no solo en PGlite. Puedes usar `@electric-sql/pglite-tools` (`pgDump`) o lo que mejor funcione; explica la elección.
- `npm run restaurar -- <archivo>`: pide confirmación escrita, avisa que reemplaza los datos actuales y hace antes un respaldo automático de lo que hay.
- Nunca se respalda ni se restaura en `NODE_ENV=production` desde estos comandos.
- Documenta los dos comandos en `docs/development/correr-local.md`, incluido cómo cargar el archivo en un PostgreSQL normal.

## Terminado cuando
- Prueba de ida y vuelta: datos sintéticos (animales, aretes, pesajes, correcciones, cuentas) → respaldo → restaurar en una base vacía → mismos datos, mismas versiones e historias.
- Una prueba carga el respaldo en PostgreSQL de servidor cuando hay `TEST_DATABASE_URL` (corre en el CI).
- `npm run lint`, `npm run typecheck`, `npm test` y `npm run test:e2e` pasan.

## Fuera de alcance
Respaldos automáticos programados, nube.
